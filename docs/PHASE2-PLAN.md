# 第 2 階段計畫：依偵測結果決定做法

> **進度 (2026-11-22)**：鎖觸控板、全鎖、外接滑鼠斷線解鎖、長按 Esc 3 秒緊急退出都已實作 (見 CHANGELOG「未發佈」)。
> 依據：偵測結果證實「內建觸控板 vs 外接滑鼠」可由事件來源裝置區分。觸控螢幕在事件層沒有收到來源資料，
> 所以鎖觸控板時不會影響觸控螢幕；全鎖時的觸控螢幕由全黑畫面擋住。待使用者實機驗收。

第 1 階段只開放「B 面清潔」與「C 面只鎖鍵盤」，因為鍵盤事件一定分得出來。
「鎖觸控板」與「全鎖」必須先證明能分辨裝置，否則會把「用來解鎖的手段」也一起鎖掉。

## 一、先跑偵測

照 `docs/PROBE-GUIDE.md` 在實機上跑 FushiProbe，再執行：

```bash
python3 scripts/analyze-probe.py --out probe-logs/report.md
```

看報告最後的結論表。

## 初步觀察 (2026-11-21，在一台觸控螢幕 MacBook Pro 上讀到的裝置)

- 觸控螢幕很可能是內建的獨立 HID 裝置 **`Kiwi`** (Transport FIFO、UsagePage 0x0D Digitizer／Usage 0x04 Touch Screen、Built-In)，
  跟 `Apple Internal Keyboard / Trackpad` 是**不同裝置**。這代表 HID 層至少分得出「是誰在送資料」，對第 2 階段是好消息；
  但事件層 (CGEvent) 能不能分得出來，還要等正式偵測結果。
- 外接滑鼠走藍牙 (Bluetooth Low Energy) 時，同樣可以從裝置資訊分辨出「非內建」。
- 如果有安裝 Karabiner-Elements 這類按鍵改寫工具，系統裡會多一個虛擬鍵盤，事件可能改由它送出。
  拂拭的鍵盤攔截在 Session 層，虛擬鍵盤送出的事件一樣會被擋；偵測時要留意這點，必要時暫時關閉這類工具各測一次。

## 二、決策表

| 偵測結果 | 能開放的功能 |
|---|---|
| 觸控螢幕 vs 內建觸控板 可區分 | C 面鎖觸控板時，觸控螢幕仍可按解鎖；B 面可用觸控板喚醒 |
| 內建觸控板 vs 外接滑鼠 可區分 | 只擋內建觸控板，外接滑鼠照常使用 |
| 觸控螢幕 vs 外接滑鼠 也可區分 | 開放「全鎖」：必須偵測到外接滑鼠才能啟用，**外接滑鼠斷線立刻自動全部解鎖** |
| 都分不出來 | C 面鎖觸控板時，只能靠外接滑鼠或計時解鎖；「全鎖」功能取消 |

## 三、各情況的實作方向

### A. 觸控螢幕 vs 內建觸控板 可區分

- 主動式 `CGEventTap` 的遮罩加入指標事件 (移動、按下、放開、拖曳、捲動、手勢類型 29～34)。
- 回呼裡用偵測找到的欄位判斷：是內建觸控板 → 回傳 nil 擋下；是觸控螢幕 → 放行。
- 「鍵盤＋觸控板」模式：鍵盤與觸控板都擋，只剩觸控螢幕能按【結束清潔】。
- B 面：全黑時，觸控板事件 (而且只有觸控板) 也能喚醒控制面板。
- 判斷欄位若是未公開的原始欄位 (raw_*)：
  - 把欄位編號與預期值寫成常數集中管理；
  - App 啟動時做「自我檢查」：若連續一段時間看不到預期值，就自動停用「鎖觸控板」並提示，避免 macOS 更新後誤擋。

### B. 內建觸控板 vs 外接滑鼠 可區分

- 同 A，判斷條件改成「內建觸控板 → 擋；其他指標 → 放行」。
- HID 層可作為輔助證據：`IOHIDManager` 監聽內建觸控板 (Built-In = 1、Digitizer/Trackpad usage) 的輸入時間，
  與事件層時間對照 (例如 30 毫秒內有內建觸控板 HID 活動才擋)。這需要「輸入監控」權限。

### C. 觸控螢幕 vs 外接滑鼠 也可區分 → 開放「全鎖」

- 開始條件：`IOHIDManager` 偵測到至少一個「非內建」的滑鼠或觸控板。
- 全鎖期間：鍵盤、內建觸控板、觸控螢幕全部擋下；只有外接滑鼠能操作【結束清潔】。
- **安全規則**：外接滑鼠的移除回呼 (device removal) 觸發時，立刻全部解鎖 (不等計時)。
- 自動解鎖計時器照常運作。

### D. 都分不出來

- 「C 面鎖觸控板」：分不出來就沒辦法「只擋觸控板」，只能擋下全部指標事件。
  解鎖方式只剩**計時自動解鎖**，或**拔掉外接滑鼠自動解鎖** (用 HID 層的裝置移除通知)。
  開始前要明確提示使用者「鎖定期間無法用觸控板或觸控螢幕解鎖」。
- 「全鎖」功能取消，從畫面上移除。

## 四、共通的安全要求 (延續第 1 階段)

- 自動解鎖計時器一定執行，攔截回呼內也檢查截止時間 (雙重保險)。
- `tapDisabledByTimeout`／`tapDisabledByUserInput` 立刻重新啟用。
- 不修改任何系統設定；App 當掉時攔截隨程序消失。
- Debug 版自動解鎖上限 30 秒。
- 新增「鎖觸控板」後，要在實機上測：
  1. 觸控螢幕能不能按住【結束清潔】；
  2. 時間到是否一定解鎖；
  3. 外接滑鼠拔掉是否立刻解鎖 (全鎖)。

## 五、開源與多國語言 (2026-11-21 決定，第 1 階段實測通過後進行)

- 拂拭要**公開開源**到 GitHub (使用者明確同意的例外，不適用「一律私人」規則)。
- 第一版支援 **10 種語言**：英文、繁體中文、簡體中文、日文、韓文、西班牙文、法文、德文、葡萄牙文 (巴西)、義大利文。
  之後可再加：俄文、土耳其文、印尼文、越南文、阿拉伯文 (阿拉伯文要另外處理從右到左的版面)。
- README 拆成兩份：`README.md` (英文，GitHub 首頁) 與 `README.zh-Hant.md`，最上面放語言切換連結。
- 待決定：授權條款 (MIT 或 Apache-2.0)、來源語言 (建議改英文)、程式碼註解語言。
- 開源前要清掉文件裡的個人裝置資訊，並確認 App 圖示可以公開。
- **曝光關鍵字**：README、GitHub 簡介與 Topics 要清楚強調「專為最新觸控螢幕 MacBook Pro (M5、PROLED XDR、Touch Screen) 設計」，方便別人搜尋到；同時寫明沒有觸控螢幕的 Mac 也能用 (B 面全黑、C 面鎖鍵盤都適用)。
- **相容範圍**：最低支援 macOS 14 Sonoma (比 26／27 再往前三版)，做成通用版 (Apple Silicon＋Intel)；沒有觸控螢幕時，介面文字自動換掉「觸控已鎖定」這類說法。
- **翻譯校稿流程** (使用者提議，功能與介面定案後做)：
  1. `scripts/export-strings.py`：把 `Localizable.xcstrings` 匯出成每種語言一份 Markdown 表格
     (欄位：key、繁中原文、翻譯、使用位置說明)，檔案開頭寫明 `%d`、`\(…)` 等變數不可更動。
  2. 使用者把 Markdown 交給 ChatGPT 校稿。
  3. `scripts/import-strings.py`：讀回校稿後的表格寫入字串目錄，自動檢查變數有沒有被改壞、有沒有漏翻。
